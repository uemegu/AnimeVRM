# 夏祭りセットのグラフィック強化：これまでの経緯と引き継ぎ（AI 向け）

このファイルは、簡易3Dの夏祭りセットの見た目をさらに良くするために、別の AI エージェント（codex など）へ渡す引き継ぎ資料。読んだあと、**まず改善案を考えて提案する**こと。実装はユーザーの承認を得てから。

開発ルールはリポジトリ直下の `GEMINI.md` に従う。返答は日本語で。

## 1. ユーザーから受けた指示（時系列・要旨）

1. 夏祭りを簡易3Dにしたい。今の一枚絵（場所 `night_festival` の `assets/textures/night-festival-far.avif`：川べりの手すり・川・対岸の提灯と屋台の灯り・山並み、空は透過）を参考に考える。**屋台も背景に必要**。
2. そのあと空を夜にして、**花火の効果**、**屋台の灯りや花火の光が人に当たる（反射する）表現**を試したい。
3. **画像生成は codex を使う**。
4. シオンの浴衣モデル `assets/models/shion/shion-private2.vrm`（characters.json の shion の `kimono`）はこの背景に合わせたもの。デモはこれを使う。
5. **もっと bloom を効かせて幻想的に。CG 感が強いので、アニメ映画っぽくしたい**。
6. **花火をもっと綺麗に**。
7. 屋台は普通は川に沿って並ぶはず。構図が難しくなるか？ → T字路案（屋台通りが川沿いの遊歩道に突き当たる）で OK が出て実装済み。
8. 時間帯 `night` を使っているシナリオは無いので、**`night` の設定は変えてよい**。場所ごとに設定を上書きできる仕組みはそのまま残す。
9. 花火が開くとき中心に**黒い丸**が出る → 修正済み（4 章）。
10. **フィルムグレインなどのノイズを足すと「っぽく」なるのでは** → 時間帯の設定にグレインを足し、`night` で有効にした。UI からはまだ設定をいじれない（JSON を直接編集する）。
11. コミットは頼まれたときだけ。

目指す方向は一貫して「**CG っぽさを消し、アニメ映画（新海誠作品のような夜祭り）の空気感にする**」。

### 光（キャラへの当たり方）

- セットはすべて光の影響を受けない素材で、灯りは描き込みとシェーダーで表している。
- キャラ（VRM・MToon）だけ実際のライトで照らす：
  - 立ち位置付近の屋台8軒の暖色の点光源と、提灯の点光源。
  - 花火の方向から花火の色で光る平行光（開いた瞬間に強く、すぐ消える）。
  - 花火の光の色は `uFlash` として地面・屋根・看板・夜空の煙・川面にも足す。複数が重なっても夜空が白くならないよう、合計に上限がある。
- 月明かり・環境光・bloom は場所の設定で時間帯より優先している（`locations.json` の `painted_festival.light`・`stage.camera.bloom`）。

### 今回足した汎用の仕組み（夏祭り以外でも使える）

- 場所の `light` に `color`・`intensity`・`ambient` を足した（省略時は時間帯のまま）。`packages/scenario/src/scene.ts` の `LocationLight`、`StageManager.applyKeyLight`。
- 場所の `stage.camera.bloom`（省略時は時間帯のまま）。`StageManager.applyBloom`。
- 時間帯の `postProcessing.cinematic.filmGrain`（`enabled`・`strength`・`size`）。シェーダーは `packages/engine/src/postprocessing/CinematicAnimeShader.ts`。
- `night` の時間帯：bloom 有効、影は青紫・明るい所は暖色寄りの色調、グレイン 0.035。

## 4. ハマったところ（同じ失敗をしない）

- **黒い丸**: 描画先は半精度浮動小数点で、花火のような明るい光は出力後も 1 を超えたまま残る。`CinematicAnimeShader` のディフュージョンは「スクリーン合成」（`1 - (1-a)(1-b)`）で、1 を超える値が来ると負になり黒く抜けた。入口で 0〜1 に収めて直した。**後処理を足すときは、1 を超える入力を前提にすること**。
- 花火が開いた瞬間は全部の星と尾が 1 点に重なり、加算合成で極端に明るくなる。最初の数十 ms はふわっと出す。
- 夜空のドームをセットの中心に置くと、川べりから陸側を向いたときドームの奥がビューアの描画距離（100m）を超えて切れ、後ろの昼の空が丸く見えた。カメラに付けて動かした。**外周の物は描画距離 100m に収める**。
- 時間帯 `night` は元々環境光が白で強く（2.0）、屋台の灯りがキャラに見えなかった。夏祭りは場所の設定で光を上書きしている。
- 屋台の横の幕を全面にすると、通りから斜めに見たとき奥の商品が隠れて色の板だけになった。横はカウンターの高さまでにした。
- シナリオの `rotationY` はラジアン。

## 5. まだ CG っぽい・弱いところ（改善の候補）

ユーザーの要望は「アニメ映画っぽく」「花火をもっと綺麗に」。現状で気になっている点：

- 屋台の柱・屋根・カウンターの側面が単色の箱で、塗りの情報がない（絵の部分との差が目立つ）。
- 屋根の縞が単純な Canvas の縞で、布のたわみや汚れがない。白い縞が bloom で光りすぎる。
- 人がいない（屋台の店主・客・人混みのシルエットがない）。夏祭りとしては寂しい。
- 地面が平坦。濡れたような照り返しや、提灯の映り込みがない。
- 花火：煙がほぼない（開いたあとに残る煙が花火の光で照らされると一気に映画っぽくなる）。音と光のずれ・連発（スターマイン）・水中花火などの演出もない。
- 空気遠近（遠くほど霞む）と、灯りの周りの空気の霞が弱い。
- 光の当たり方：花火の光は平行光なので屋根の下でも同じように当たり、影で遮られない。キャラの縁に灯りの色が回り込む（リムライト）表現がない。
- 遊歩道の端（x=±30 より先）、屋台の裏、通りの奥（z=15 より先）は石畳だけで簡素。
- 夜専用。夕方（花火前の薄明）のバリエーションがない。

## 6. 守ること・やらないこと

- 画像生成は **codex の built-in image generation**。下書き（寸法どおりの区画図など）と絵柄の参照画像を渡し、「区画・輪郭の位置を動かさずに描く」と指示する。透過画像の変換は `avifenc -s 6 -q 85 --qalpha 100`（`GEMINI.md`）。
- 極端なクローズアップは禁止。2ショット・引きを混ぜる（`GEMINI.md`）。
- 表情ウェイトは 1.0 か 0.0（`GEMINI.md`）。
- UI に絵文字を使わない（`GEMINI.md`）。
- 他の場所・シナリオの見た目を壊さない。共通の仕組み（StageManager・後処理・時間帯の設定）を変えるときは、夏祭り以外の場所でも撮って確かめる。`night` 以外の時間帯は勝手に変えない。
- 揺れもの（髪・スカート）は簡単なバネなので、風を強くしない（0.1 前後まで）。
- 実現が原理的に難しいことは、試行錯誤を重ねる前に理由を添えて早めに伝える（`GEMINI.md`）。
- コミットはユーザーに頼まれたときだけ。

### 8.1 今回の判断と見た目の変化

変更前の6カットを確認すると、屋根の白い縞が提灯と同じくらい発光し、花火が重なる部分は白い塊になっていた。全画面の拡散・グレイン・色収差も細部を読みにくくしていたため、まず発光体と非発光面を分離する方針にした。

- 屋根・看板・カウンター前板の明るさと花火から受ける光を下げた。屋台の中の絵は灯りのある空間として残している。
- 赤い提灯は白飛び抑制を入れた直後に発光感が弱まったため、中心の暖色成分を強めて再撮影・調整した。
- 花火の粒を小さくし、粒の周囲のハローを弱め、開花直後の粒の立ち上がりを遅くした。その後、粒の明るさと大きさを再調整し、色と尾の分離を保ちながら発光感を戻した。
- グレイン・色収差・背景ぼかしを弱め、浴衣の柄・屋台の商品・看板を読みやすくした。シャープ処理を強めて精細に見せる方法は使っていない。

現在の主な調整値：

- `night.postProcessing.bloom`：strength `0.3`、radius `0.35`、threshold `0.95`。`deepGlow` は enabled `true`、core `1.1`、halo `0.6`、haze `0.22`。
- `night.postProcessing.cinematic`：diffusion.strength `0.06`、filmGrain.strength `0.009`、filmGrain.size `1.15`、chromaticAberration.offset `0.0003`。
- `painted_festival.stage.camera.bloom`：strength `0.36`、radius `0.3`、threshold `1.0`。deepGlowはnightから継承。

### 8.4 次に作業する人への注意

- 第5章の「白い縞が光りすぎる」「煙がほぼない」は今回対応済み。ただし布のたわみ・木目・塗りの情報量はまだ増やしていない。

- 地面の局所反射、屋台の湯気、人混み、花火の光の遮蔽、周辺の簡素な地形も未対応。

## 9. 人物の陰影とにじみ（Claude が引き継いで仕上げ、2026-10-03）

指示：「人の陰影をはっきりさせつつ、人をぼんやり光らせたい。光が当たっているところがぼんやりと輝く」（映画の加工前後の資料つき）。codex が `CharacterGlow.ts`（人物の明部だけをぼかして足す後処理）と時間帯の `postProcessing.characterGlow` を作ったところでレート制限になり、Claude が調整した。

- にじみの足し方を変えた。しきい値をなだらかにし（明るい所ほど強く光る）、人物の上ではにじみを半分にして、輪郭のすぐ外側では全部出す。足し方はスクリーン合成に近い形にして白飛びを防ぐ。しきい値が低すぎて顔全体がピンクに白飛びし、目鼻が読めなかったのを直した。
- 陰影をはっきりさせるため、`painted_festival` の環境光を下げ（0.55→0.32）、月明かりを主光にした（1.5→2.1）。屋台の点光源は 8→6。
- `night.postProcessing.characterGlow`：strength `1.4`、radius `0.024`、threshold `0.22`。
- 確認：夏祭りの全カット、腰から上の寄りの試し撮り（`scratch/painted-festival/draft-glow.json`）、校門の night。

残り：顔は MToon の作りで陰がほとんど付かないので、顔の陰影は増えていない。濃い色の浴衣は陰影が見えにくい。

### 9.1 目のケアと服・肌の輪郭なじませ

- 目が光りすぎる：目のハイライトは自発光（`ToonShader.ts` の `applyEyeGlow`）で、夜は白を大きく超え、人物のにじみとブルームで目が光って見えた。目のメッシュ（`isEyeMaterial`）を `EYE_LAYER`（7）にも載せ、目だけの深度マスクを描く。`CharacterGlow` では、目が一番手前にある画素を白の少し下（`uEyeCap` 0.9）に抑え、にじみの元からも外す。ブルームより前のパスなので、ブルームにも拾われない。前髪の奥の目は対象外。
- 輪郭を背景になじませる処理（ライトラップ、`LightWrap.ts`）は、髪以外が 0.3 倍。夏祭りだけ服・肌も髪と同じ強さにした。
- ユーザーの指示で、目の抑えと輪郭のなじませは**夏祭りだけ**の設定にした：場所の `stage.character`（`eyeCare`・`lightWrapBody`）。ほかの場所は従来どおり（目の抑えなし、なじませ 0.3）。
- 確認：夏祭りの寄り（目を開けた表情）、校門の朝、trio の廊下。

### 9.2 肌が絵の具で塗ったように見えた件

- 原因は Bloom ではなく `CharacterGlow`。半径の大きい円盤から 40 点だけまばらに拾ってぼかしていたため、肌に斑（塗りムラ）が出ていた。にじみを切ると肌はきれいになることで確認した。
- 作り直し：人物の明部を半分の解像度に抜き出し、4分の1の解像度で縦横に分けたガウスぼかしを2回かけてから足す。斑が消え、なめらかなにじみになった。
- ユーザーの感想：見え方は時間帯「昼・逆光」（`indoor_dark`）が一番きれい。night はそれより霞んでピンク寄り（色調・拡散・明部圧縮）。night を寄せるかは未決。

### 9.3 にじみを「人物の後ろに出す光」に作り直し

- ユーザーの参考（3ds Max の撮影処理の資料。加工前→加工後で、人物の中はセルルックのまま、白いシャツなど明るい部分の光が輪郭の外へぼんやりあふれる）に合わせた。人物の上にもにじみを足していた前の作りは、セルルックが崩れるので不可とされた。
- `CharacterGlow`：明部を抜き出してなめらかにぼかし、**輪郭の外側（背景側）にだけ**足す。人物の上には `uInside`（0.05）だけ。人物の上かどうかはキャラのマスクだけで判定する（シーンの深度との比較は、前髪の下の顔で精度が足りず、顔に斑が出た）。
- `night.postProcessing.characterGlow`：strength `2.8`、radius `0.03`、threshold `0.1`。

### 9.4 灯り・花火をもっと輝かせ、昼・逆光くらいの明るさに

- ユーザーの好み：見え方は時間帯「昼・逆光」（`indoor_dark`）くらい明るい方がよい。灯りと花火はもっと輝かせたい。輪郭の外の光は幅が広すぎる。
- `night`：色調（拡散・グレーディング・彩度）と人物の素材（色・影色・影のずれ・環境光のならし）を `indoor_dark` と同じ値にした。影の色味だけ夜の紺紫（`#1c1646`）、明部は白寄り（`#fff4e8`）。
- `painted_festival` のブルーム：strength `0.55`、radius `0.5`、threshold `0.8`、deepGlow 無効（明部の圧縮が灯りの輝きを抑えていた）。
- 提灯・裸電球・灯りのにじみ・花火の粒を 1.4〜1.7 倍に明るくした。花火がキャラを照らす光は少し弱めた（2.4→1.7）。
- `characterGlow`：strength `1.3`、radius `0.014`（幅を半分以下に）。目の抑えは白の 0.75 まで。

### 9.5 人物の白飛び防止と、花火の逆光リム

- ユーザー指摘：花火が続けて光ると人物の明るい部分が白飛びする。後ろで花火が光っているなら、正しくは逆光で体の輪郭にリムライトが出るはず。
- 原因：花火の光は平行光で、MToon は後ろからの光でも人物全体を照らすため、背後の花火が顔を正面から照らしていた。
- 新しい後処理 `packages/engine/src/postprocessing/CharacterFinish.ts`（色調補正の後、人物のマスクの上だけ）：
  - 逆光リム：3D背景が `scene.userData.characterRim`（色と画面上の光の位置）を出すと、輪郭のうち光の方を向いた側に細いリムを描く。白寄りの色で、縁で一番明るく内側へ消える。
  - 明部の上限：場所の `stage.character.highlightCap`（夏祭りは 0.93）に向けて、人物の一番明るい色成分を滑らかに抑える（色味は保つ）。背景は抑えない。
- `Fireworks.ts` の `splitBacklight`：花火の方向がカメラの向き（=人物の背後）に近いほど、平行光を弱めてリムに回す。カメラ側の花火は従来どおり人物を照らす。夏祭りを破棄するとき `characterRim` を消す。
