# 元絵の質を保つ簡易3D背景

このプロジェクトの「簡易3D」は、描き込まれた背景画の質感を、軽い立体に貼って複数方向から撮れるようにしたセット。簡略化するのは形状の複雑さであり、絵の密度や撮影できる方向ではない。

**空と雲は Three.js の既存 `SkyBackground` で描画する。窓越しの空も含め、生成する壁・窓・遠景の画像に空を描き込まない。** 屋内の窓では窓枠・カーテン・窓外の樹木や建物を残し、空に当たる部分だけを透明にする。画像生成には `transparent_background: true` を指定し、AVIF の alpha を保つ。窓の裏を不透明な壁・箱で塞がず、実画面で窓から Three.js の空が見えることを確認する。`layers.background.url` は共通の `/textures/painted-classroom/sky-only.png` を使用する。

通常は運動場・中庭・商店街の方式を選ぶ。各建物の前・横・後ろに、その面に対応する絵をUVで貼る。床はタイル、屋根や家具は実形状、植栽は透明な絵の交差板、遠景は外周の板に分ける。正面の一枚絵を箱に投影しただけで完成扱いにしない。カメラ投影はユーザーが撮影方向を限定したセットを求めた場合に検討する。

以下のパスとコマンドはリポジトリルート基準。

## 1. 最初に見るもの

- `GEMINI.md`。画像形式、無音での検証など、このプロジェクトのルール。
- 元絵を**実際に画像として開く**。既存の場所なら `assets/studio/locations.json` の layers と、その画像ファイルから探す。AVIFを表示できなければ `avifdec 元絵.avif scratch/<作業名>/reference.png` で確認する。
- 基本の見本：`packages/engine/src/scene/shopping-street/` の `README.md`、`layout.ts`、`ShoppingStreet.ts`、`Buildings.ts`、`StreetFurniture.ts`。
- 校舎・中庭・広い屋外：`packages/engine/src/scene/painted-ground/README.md`、`layout.ts`、`PaintedGround.ts`。`courtyard` は同じセットを位置をずらして使用している。
- 開放した屋台や夜景が必要なら `packages/engine/src/scene/painted-festival/Stalls.ts` と `README.md`。READMEの説明とコードが食い違う場合、現在のコード・スキーマを確認する。

元絵から、建築様式、壁と床の素材、窓の中身、店先の道具、植栽の密度、色、光の方向を短く整理してから作り始める。寸法や隠れた面は推定してよいが、元絵にない別の街・建築様式に置き換えない。

## 2. 配置と素材を先に分ける

`layout.ts` にメートル単位の寸法、配置、撮影点を集約する。地面は y=0、上は +y。方角はセットごとに定義する（運動場・商店街は北を -z としている）。

- 会話時の人物の立ち位置を原点付近に置き、通常の slots と既定の会話カメラが使えるようにする。
- 元絵の通路幅、建物の高さ、家具と人物の比率を揃える。建物を不自然に高くして背景の穴を隠さない。
- 前だけでなく左・右・後ろに何が見えるかを配置する。遠景で外周を覆っても、近くの建物の側面・背面は省略しない。
- 同じキャンパスなどを複数の場所から使う場合は、セットの配置とその場所の人物・カメラ座標を対応させる。

| 要素 | 作り方 |
| --- | --- |
| 建物 | 厚みのある箱＋面ごとの正投影立面。上階と下階の高さを合わせる |
| 屋根・ひさし・柱・手すり・看板 | 突き出す部分は実形状。模様・文字・風合いは面の素材 |
| ベンチ・テーブル・街灯・A型看板 | 脚、座面、背もたれ、厚みを作る。近くで撮る家具を一枚の切り抜きで済ませない |
| 花壇・プランター | 中空の囲い＋内側の土＋植栽。花の素材に箱や鉢を描かない |
| 木・低木・花 | 透明な切り抜きを固定の交差板にする |
| 地面 | 広い連続面＋繰り返しタイル。通路に穴・裸地・段差が残らないようにする |
| 遠景 | 樹木帯・町並みの切り抜き。撮れる方向を覆う外周へ配置 |

## 3. 絵の素材を用意する

画像生成が必要なら、その環境で利用できる `imagegen` スキルを読み、元絵を参照画像として渡す。生成指示の雛形は [references/texture-prompts.md](references/texture-prompts.md)。今回の元絵に合わせて具体的な材料・色・密度を記述する。

- 建物は透視図ではなく、真正面の正投影立面。画面の端まで建物を描き、空・地面・立体で作る家具を含めない。
- 地面は上から見た継ぎ目のないタイル。遠近感、地平線、家具の固定影を描かない。
- 花や木は透明背景。色付きのぼけた背景、絵の中の花箱、落ち影を残さない。
- 生成した絵も開いて確認する。指定した階の比率・境界・透明領域が実際に合っているかを測り、形状／UVを合わせる。プロンプトの指定値を無条件に信じない。
- 元の2D背景を残し、ランタイム用素材は `assets/textures/<セット名>/` に置く。生成指示は実装ディレクトリの `PROMPTS.md`、参照・元PNGは `scratch/<作業名>/` に保存する。

通常は `avifenc -s 6 -q 85 input.png output.avif`、透過は `--qalpha 100` を付ける。細かな文字や花で劣化が見えたら品質を調整する。元PNGだけでなく変換後を実画面で確認する。

## 4. 立体を組み、光と質感を合わせる

実装上の寸法、UV、素材、統合、解放の具体例は [references/implementation.md](references/implementation.md) を読む。

描き込みに光が含まれる素材は `MeshBasicMaterial`、`SRGBColorSpace`、`toneMapped: false` を基本とする。二重の照明・トーンマッピングや霧で、元絵を白く薄くしない。素材に必要な陰影は残し、人物の照明は場所の `light` で元絵の方向・色に合わせる。

木や花は通常3枚を60度ずつ交差させる。板は世界に固定し、カメラを向くたびに回さない。箱や幹の足元を地面／土に接地する。看板は必要な両面を読めるようにする。

絵に含まれるひさしや花箱と実形状を重ねて二重にしない。窓・店内・壁の細部を、単色の平面や手続き的な模様だけで置き換えない。立体の木目・瓦など補助的な模様には CanvasTexture を利用できる。

## 5. エンジンと場所に登録する

新しい組み込み背景では次を揃える。既存セットの調整なら必要な箇所だけ変更する。

1. `packages/engine/src/scene/<セット名>/` に非同期の `load...(): Promise<THREE.Group>` と `dispose...()` を作る。
2. `packages/engine/src/stage/environments.ts` の `BUILTINS` に load/dispose を登録する。
3. `packages/scenario/src/scene.ts` の `BUILTIN_ENVIRONMENTS` にIDと表示名を登録する。
4. `assets/studio/locations.json` の `presets` に場所を追加する。`environment.model`、配置、人物の光、camera、slots、thumbnail を設定する。屋外と窓から空が見える屋内は `layers.background.url` に `/textures/painted-classroom/sky-only.png` を使う。
5. `assets/scenarios/demo/<デモID>/scenario.json` に方向確認用のカットを作る。場所・シナリオ編集は `.agents/skills/scenario-authoring/SKILL.md` の形式・検証方法に従う。
6. Pagesに出す場合は `studio/pages/catalog.ts` と `studio/pages/collectAssets.ts` にデモと素材を登録する。別ディレクトリの共有素材も収集対象にする。

必要以上にJSON全体を整形し直さず、ほかの場所・キャラ・作業中の変更を保つ。

## 6. 同じ位置から回して確認する

**正面だけのスクリーンショットでは完了にしない。** まず人物なしで、カメラ位置を固定し target の方向を変えた4カットを作る。

商店街の例（高さも固定した純粋な水平回転）：

| カット | position | target |
| --- | --- | --- |
| 正面 | `[0, 1.65, 3]` | `[0, 1.65, -17]` |
| 左90度 | 同じ | `[-20, 1.65, 3]` |
| 右90度 | 同じ | `[20, 1.65, 3]` |
| 後ろ180度 | 同じ | `[0, 1.65, 23]` |

場所に合わせて距離・FOVを調整してよい。左右に数十cm移動しただけの写真を「左右を向いた確認」にしない。

その後、店先・建物の角を斜めから、通りの奥から逆向き、屋根と厚みが見える俯瞰、人物を置いた既定の会話カメラを確認する。夕方にも使う場所なら夕方を追加する。

```sh
npm run validate
npm run typecheck
npm run shot -- demo/<デモID> --no-dialogue --no-hud
```

出力は `scratch/shots/demo/<デモID>/`。画像を実際に開き、側面の空白、絵の引き伸ばし、家具の重複、透過の四角、足元の浮き、遠景の切れ、人物への被りを確認して直す。撮影スクリプトは無音。描画距離が不足する場合は `stage.camera.far` をセットの大きさに合わせる。

Pages連携を変更した場合は、`PAGES_OUT_DIR="$PWD/scratch/<セット名>-pages" npm run build:pages -w studio` で素材込みのビルドを確認する。生成される `docs/` を手で編集しない。スキーマや検証処理を変更した場合は scenario の関連テストも実行する。

## 7. 次の制作へ引き継ぐ

セットの `README.md` に元絵、座標と寸法、使う場所・デモ、素材の分担、共有素材、撮影範囲、実際の制約を残す。生成指示は `PROMPTS.md` に残す。

完了時は方向別の実画面、使える場所ID、検証結果を伝える。交差板の植栽や絵で表した室内は、近距離・真上・入店には限界がある。確認した撮影範囲に即して説明し、未確認の自由移動まで保証しない。
