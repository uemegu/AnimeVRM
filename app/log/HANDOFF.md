# HANDOFF 引き継ぎメモ

## 現在の実装状況

- **ゲームループ & 進行**:
  - 21日間サイクル（朝・午前・昼・放課後・夜）。Day 11 朝のボタンでルート分岐、Day 21 夕方の神社で決着。
  - 移動場所選択（学校マップ）、日中強制割り込みイベント、当日やり直し機能。
  - 土日は休日: 朝イベントなしで昼の行き先選択（街マップ）1回のみ → 夜。ヒロインは私服モデル。遊園地・水族館はフラグで解放。
  - エンディングは★方式（ルートごとに★2つで TRUE、足りなければ GOOD、時間切れで BAD）。仕様と好感度の基準は `FEATURES.md`「エンディング」。
  - 一度見たイベントは繰り返さない。汎用（fallback）は何度でも、場所を指定した汎用が優先。下校時の強制イベント（`timeSlots: evening`）、雨の日（`data/calendar.ts`）、日付の指定（`days`）。
- **画面構成（pages分割）**:
  - `src/pages/` 配下に各画面（`TitlePage`, `ScenarioPage`, `ActionSelectPage`, `NightRoomPage`, `EndingPage`）を分割独立。
  - `App.tsx` は画面ルーティングとゲーム進行（フェーズ遷移・セーブ/ロード・就寝）に集約。シナリオ再生・会話履歴・確認ダイアログは `src/hooks/`、表示する場所・キャラの判定は `services/stage/sceneView.ts`。
  - 表示言語は `LanguageProvider` / `useLanguage()` で参照（props で中継しない）。
- **シナリオ & 会話**:
  - Headless型ステートマシン（`ScenarioEngine.ts`、Vitestテスト対応）。
  - シナリオは `assets/scenarios/<category>/<id>/scenario.json`（ボイスも同じディレクトリ）。発生判定用のメタ情報は `src/data/scenarioIndex.json` に自動生成し、本文は再生直前に遅延ロード（`ScenarioRepository`）。書き方は `FEATURES.md`。
  - 行動ヒント情報（場所・フェーズ・ヒント文・滞在キャラID）は各シナリオの `actionHints` で管理。
  - 夜の電話・メールも `assets/scenarios/call|mail/` のマスターデータ。条件を満たすものが1人1件ずつ優先度順に届き、完了は進行履歴に残る（`ScheduleManager.getNightCommunications`）。
  - `ScenarioPackage.availability` による発生条件（前提シナリオ/選択肢、時間帯、日数、場所）、優先順位、セーブ対応の進行履歴。
  - 条件の指定例と時間帯・AND/ORの意味は `FEATURES.md` を参照。
  - タイピング演出、ルート準拠のボイス再生終了＆文字数同期AUTO送り、選択肢UI、幕間スライストランジション。
  - **シナリオ原稿の正は `/Users/ueda/git/novels/5秒の告白/`**。共通・3ルート（導入・展開・結末3種）・夜の連絡・日常を全部 `scenario.json` 化済み（2026-10-04）。旧設計のシナリオは削除し、旧 daily_* は場所ごとの汎用シナリオとして残した。
  - 演出の追加：一枚絵（`cg`）・カットイン（`cutin`）・雨（`rain`）、選択肢の出現条件（好感度・フラグ）とルート分岐の救済（`choiceFallback`）、メールのスタンプ・写真・送信取り消し・複数の反応、音声のみの電話、その日のうちの条件（`sameDay`）と電話直後の続きの連絡。書き方は `FEATURES.md`。
  - 足りない素材（モーションのポーズ絵・BGM・SE・簡易3D背景・モデル）と、原稿との差・確認事項は `app/scenarios/5byou_resources.md`。
- **3D描画 & ビジュアル**:
  - Three.js / VRM / 多層背景（AVIF、神社・神界・学校各所・運動場・自室等）、全自動リサイズ、ポストプロセス（Bloom/GodRays/薄明光線等）。
  - ルート準拠の `divine`（神聖・逆光シルエット＋黄金リムライト）を含む時間帯・演出プリセット。
  - ルート準拠のMSAA (4 samples) + SMAAアンチエイリアス、Retina解像度スケーリング。
  - 待機モーション、表情補間、自動まばたき。
  - 感情演出（頬赤・怒りマーク・涙・汗・目が泳ぐ・文字演出・残像）と画面演出（集中線・瞼・暗転）。シナリオの書き方は `FEATURES.md`。
- **オーディオ & リップシンク**:
  - BGM ID管理（タイトル、プレイ中、夜自室）、シームレス継続、夜間音量縮小。
  - サウンドミュート機能（ヘッダー・タイトル画面から即時切替）。
  - 音声（BGM・SE・ループSE・ボイス）の再生とミュート（保存含む）は共有の `soundManager` に集約。音声アセットは MP3 形式に統一。画面側で `new Audio()` や `isMuted` を扱わない。UI効果音は `sePresets.ts` のIDで鳴らす。
  - Web Audio API / WASMによる母音解析リップシンク（ミュート時も口パク解析は維持）。
  - 開口度も WASM で録音の RMS・周波数の特徴から計算し、app・電話・Studio で共有。キャラ別の固定倍率は使わない。音声解析は WASM のみで行う。
- **プリロード & ローディング**:
  - `preloadManifest.json` による静的アセットサイズ自動集計と事前ロード画面。
  - 幕間トランジション中のオンデマンド非同期ロード。シナリオを始めた幕間は、そのシナリオに出るキャラの先読み（モデル・モーション・描画の準備）が済むまで明けない（上限8秒）。途中で人が増えても止まらない。
- **UI & モーダル（白基調・ライトテーマ統一）**:
  - **ヘッダー**: LOG（ノート）, AUTO（再生）, SHARE（Xロゴ/ショートカットS・セリフ合成キャプチャ付き・モバイルはWeb Share API、PCはクリップボード画像コピー＋1.5秒後Web Intentオープン）, MUTE（スピーカーON/OFF）。全ボタン（固定サイズ78px×34px）とステータスバッジのサイズ統一、アイコンと文字の上下中央完全整列。言語切替およびINFOボタンは撤去。
  - **シェア通知（ShareToast）**: 白基調ガラスモーフィズム、絵文字なし、操作結果通知＆「今すぐ開く」アクションボタン。
  - **セーブ/ロードモーダル**: 3スロット対応、タイトル規約準拠（絵文字・補足削除）、スロット高さ統一、進行度・親密度横並び表示。
  - **直近３セッションの会話履歴モーダル**: blockスクロール、最下部自動スクロール、選んだ選択肢の記録・専用表示、ボイス再聴取。
  - **夜の自室コミュニケーション（TV電話・メール）**:
    - 着信バイブ音（`phone_vibe.mp3`）ループ再生（応答・拒否時に即時停止）、ヒロインテーマカラー（黄・赤・青）の明るいアイコン背景を持つ着信通知カード（電話バッジ等なし・メッセージ非表示）および新着メール通知カード（本文プレビュー表示・添付メール通知音 `mail_notification.mp3` 単発再生）。
    - 画面下部からスライドインするスマートフォン枠内でのTV電話（室内明ライティングの私服VRM顔アップ・インカメラ構図、CRT走査線ディスプレイ効果、通話時間、画面下部の通常DialogueBox・ChoiceBoxによるセリフと選択肢進行）。
    - スマートフォン枠内でのLINE風メール（各ヒロインの淡いテーマカラー円形背景を持つアイコン、トーク履歴、返信選択肢、相手のリアクション返信演出・通知音、既読表示）。
    - 返事の選択に応じた好感度加算とシナリオ分岐フラグの記録・セーブ連携。
    - 自室サイドバーは元の白基調構成（ヘッダー、ヒロイン好感度メーター、就寝するカード、セーブ、ロード、やり直すカード）を完全維持。
  - **移動場所選択 / 自室コマンド / ライセンス確認 / 共通確認ダイアログ**。

## 設計上の重要留意事項

- **白（ライトテーマ）基調**: モーダルやパネルは白基調。絵文字のUI使用禁止（SVG/文字を使用）。
- **キャラクターのテーマカラー厳守**: アオイ=黄色、エミリ=赤、シオン=青。
- **並びのボタン・ラベルのサイズ統一**: 同列に並ぶボタン・バッジは高さ・幅を揃える。
- **デザイン先行確認**: UI変更時は自動テスト前に画面キャプチャでユーザー承認を得る。
- **Studio との共有**: 素材はリポジトリ直下の `assets/` を Studio・Pages 版と共有する（旧ルートのビューアは 2026-09-27 に削除）。描画（`StageManager`・`StageAvatar`・`ScrollingBackground`・シェーダー・ポストプロセス）は `packages/engine` にあり、Studio のプレビューと共有する（app 側に複製を置かない）。時間帯・場所の見た目は `assets/studio/time-of-day.json`・`locations.json`（Studio のシーン設定）で、app は `data/timeOfDayPresets.ts` などから読むだけ。キャラ定義の正は `assets/studio/characters.json`（`characters.ts` とずれるとテストが失敗する）。シナリオ JSON の形式は `packages/scenario` のスキーマが正。シーンの演出（アバター・カメラ・タイムライン）の型はアプリでもスキーマの型をそのまま使い、それ以外のアプリの型はスキーマとずれると型チェックで失敗する。
- **囁き声・開口度**: WASM で音声の PCM の特徴だけから計算する。キャラ名・ファイル名による補正や JS 解析へのフォールバックは使わない。旧データの `voiceWhisper` は読み込み互換のため残すが開口度には適用しない。WASM のソース・バイナリ・Worklet はセットで更新する。
- **ポージング・構図の規則**: 座りは席（`locations.json` の `seats`）でだけ、流れる背景は横から、場所が変わると自動で暗転。`npm run validate` と `npm run check:framing` で確かめる（GEMINI.md）。
- **メモリ**: three.js のキャッシュは上限付き（`services/loader/assetCache.ts`）。`THREE.Cache.enabled` を直接いじらない。
- **シナリオ発生条件**: 未指定項目は制限なし。優先順位は大きい値を優先し、同値時は定義順。休日時間帯は土日として判定。
- **簡潔な記録**: 作業ログや引き継ぎメモにコードを見ればわかる細部・数値を書かない。
