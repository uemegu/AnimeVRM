# 感情演出・画面演出の移植（Studio 化 第8段階）

## 作業目的
旧ルートにしかなかった演出を、app と Studio で共有する描画に移し、シナリオ JSON から使えるようにする。

## 主な変更要点
- アバターの演出：頬赤（目の潤み付き）、怒りマーク、涙、目が泳ぐ、モーションの速さ、速い動きの残像は、指定を変えるまで引き継ぐ。文字演出と汗はそのシーンで1回だけ。
- 画面の演出：暗転・瞼を閉じる・まばたき（`screenTransition`）と集中線（`focusLines`）はそのシーンだけ。舞台の中に重ねるので、メッセージウィンドウは隠れない。
- セリフ途中のキー（`transitions`）でも同じ項目を指定できる。
- アプリのシーン演出の型（アバター・カメラ・タイムライン）は共有スキーマの型を使うようにした（二重定義をやめた）。使われていなかった旧形式の項目（カメラの寄り・目線のずれ指定など）はスキーマから外した。
- 文字演出は表示言語に合わせる。

## 動作確認結果
- 既存8シーンの見た目が変わらないことをスクリーンショットで確認。
- Studio のプレビューで各演出が出ることを確認。型チェック・全テスト通過。

# 旧ルートのシナリオを JSON に移す（Studio 化 第8段階）

## 作業目的
Pages で再生するため、旧ルートの TS シナリオ（5秒告白PVを除く16本）を共有形式の JSON にする。

## 主な変更要点
- `assets/scenarios/demo/` に置いた。demo はゲーム本編の目次（`scenarioIndex.json`）に載せない。
- 形式に追加：シーンの `end`（ここでシナリオを終える）、`ambience`（ループする環境音。引き継ぐ）。`seUrl` は1回鳴らす音とした。
- 選択肢のシーンにセリフがあったものは、セリフのシーンと選択肢だけのシーンに分けた（開発ルール）。
- 公園（並木）の中景は白を透過にした画像に作り直した。中景・近景は画面に貼り付く置き方（旧ルートと同じ）。

## 動作確認結果
- 全16本がスキーマ・リンクの検証を通過。Studio のプレビューで各シナリオの見た目を確認（公園・カフェは旧ルートと比較）。

# シナリオ再生と Pages の差し替え（Studio 化 第8段階）

## 作業目的
Studio でシナリオを通して再生でき、GitHub Pages を再生だけの静的版にする。

## 主な変更要点
- 分岐をたどって舞台を引き継ぐ進行処理を共有パッケージに置いた（`ScenarioRunner`）。app のゲーム進行とは別。
- 描画が読む素材の URL にベースパスを付けるようにした（Pages はサブパスで配信するため。app は変わらない）。
- `docs/` は Pages 版の出力先になった。旧ビューアのビルドは `dist/` に出す。

## 動作確認結果
- Pages 版をサブパスで配信して16本すべて最後まで再生できること、素材の読み込み失敗がないことを確認。
- app の既存シーンの見た目が変わらないことを確認。型チェック・全テスト通過。

# 暗い店内の光と、窓の外の明るさ（カフェ監視）

## 作業目的
旧ルートの「室内・暗2」とカフェの窓の外の明るさを移す。暗い店内と明るい屋外の対比に意味がある場面のため。

## 主な変更要点
- 時間帯に `indoor_dark`（室内・暗）を追加。場所の遠景に明るさ（露出）、キャラに日なたの明るさ（`daylight`）を指定できるようにした。
- シナリオの表情は6種類（neutral・happy・angry・sad・relaxed・surprised）に限った。旧ルートで効いていなかった表情名（relax など）は意図に合わせて置き換えた。

## 動作確認結果
- カフェ監視の見え方を旧ルートと比較し、店内の暗さと窓の外の明るさの対比が同じになったことを確認。全テスト通過。

# モーションの指の動き

## 作業目的
Studio のモーション画面を作る中で、app のモーションの読み込みが指のボーンを移していないことがわかった（旧ルートは移していた）。

## 主な変更要点
- 共有の描画（`StageAvatar`）でも FBX の指の動きを移すようにした。待機モーションなどで指が自然に曲がる。

## 動作確認結果
- 既存8シーンのスクリーンショットで崩れがないことを確認。全テスト通過。
