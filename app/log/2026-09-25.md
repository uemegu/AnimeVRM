# 2026-09-25 作業ログ

## 作業目的
土日（学校が休み）の休日行動を追加する。

## 変更要点
- 土日は朝の登校イベントを挟まず、昼の「休日の行き先」選択から1日が始まる。休日の行動は1回のみで、終わると夜の自室へ進む。
- 休日の行き先選択は街マップ（`town_map`）を使用。初期の行き先は公園・商店街・映画館・自宅。
- 遊園地・水族館はフラグで解放（`unlock_amusement_park` / `unlock_aquarium`）。商店街のエミリの福引きイベント、公園のアオイの散歩イベントで誘う選択肢を選ぶと立つ。
- 休日のイベントではヒロインが私服モデル（`-private`）で登場する。
- 休日用の短いイベントを追加（公園=アオイ、商店街=エミリ、映画館=シオン、遊園地=エミリ、水族館=アオイ、自宅=誰とも会わない）。
- 「1日をやり直す」は休日なら昼の行き先選択から再開する。
- 映画館・遊園地・水族館は専用背景がないため、既存背景で代用中。

## 動作確認結果
- 型チェック・ユニットテスト全件成功（休日の進行・行き先・解放・シナリオ決定のテストを追加）。
- ミュート状態のブラウザで、土曜の街マップ表示 → 公園でアオイ（私服）と会話 → 水族館の約束 → 就寝 → 日曜の行き先に水族館が増えることを確認。

## 作業目的（リファクタリング）
シナリオをコードから JSON に外出しし、音声・言語・再生処理の置き場所を整理する。

## 変更要点
- **シナリオの JSON 化と遅延ロード**:
  - `public/scenarios/<category>/<id>/scenario.json` に1本1ディレクトリで配置し、ボイスも同じディレクトリへ移動（相対パスで参照）。
  - 発生判定に使うメタ情報だけを `src/data/scenarioIndex.json` に自動生成し（Vite プラグイン、開発中は保存で再生成）、本文は再生直前に読み込む（`ScenarioRepository`）。
  - 汎用シナリオの特別扱い（ID 直書き）を `fallback`、出会いイベントのフラグ条件を `availability.unlessFlags`、背景の ID 部分一致判定を `location` に置き換え。
  - 移行前後で全日・全フェーズ・全場所のシナリオ選択結果が一致することを確認（704通り）。
- **App の分解**: シナリオ再生（AUTO 送り・シーンごとのボイス/SE）を `useScenarioPlayer`、会話履歴を `useDialogueHistory`、確認ダイアログを `useConfirmDialog` に移動。時間帯・場所・表示キャラの判定は純粋関数（`services/stage/sceneView.ts`）に。
- **音声**: MUTE の保存・復元を `soundManager` に移し、MUTE ボタンはサービスを直接参照。UI 効果音はプリセット ID（`sePresets.ts`）で鳴らす。
- **言語**: `LanguageProvider` / `useLanguage` を追加し、各画面への `lang` の受け渡しを撤去。
- 時間帯名の重複定義を `data/phases.ts` に集約。
- 選択肢の10秒タイムアウトで二重に選択されてエラーになる不具合（開発時）を修正。

## 決定事項
- 強制イベント（出会いイベント）の背景は、直前に選んだ場所ではなくシナリオの舞台（`location`）を表示する。
- UI 効果音の音量をプリセットに統一（移動先クリック音は他のホバー音と同じ音量に）。

## 動作確認結果
- 型チェック・ユニットテスト全件成功（シナリオファイル検査・表示判定のテストを追加）。
- ミュート状態のブラウザで、タイトル → Day1 朝 → 午前(教室・選択肢) → 昼(図書室・AUTO) → 放課後(屋上) → 夜 → 就寝 → Day2 朝 → 出会いイベント → 場所選択、女神実験シナリオを確認。シナリオとボイスがディレクトリから遅延ロードされることを確認。

## 作業目的（夜の電話・メールのデータ化）
電話・メールを「1日目固定」のコードから、条件で届くマスターデータに変える。

## 変更要点
- 電話・メールを `public/scenarios/call/` `mail/` の JSON に移し、行動シナリオと同じ発生条件（日付範囲・フラグ・先行シナリオ）と優先度で選ぶ。
- 1人のヒロインからは一晩に1件。応答・着信拒否・既読で完了扱いになり、進行履歴に残る（以後は届かず、`after` 条件の先行条件にも使える）。
- 発生条件に `requireFlags`（指定フラグがすべて立っていれば発生）を追加。
- 日付入りのフラグ（`night_call_completed_day1_aoi` 等）は廃止。

## 決定事項
- 既存4件の条件は暫定: アオイの電話は1日目のみ（優先度1）、3人のメールは1〜3日目。1日目の夜はアオイが電話になるため、アオイのメールは2日目に届く。

## 動作確認結果
- 型チェック・ユニットテスト全件成功（今夜届く電話・メールの選び方、電話・メールファイルの検査を追加）。
- ミュート状態のブラウザで、夜の自室でアオイの着信 → 通話 → エミリのメール返信 → シオンのメール通知の順に届き、アオイからは2件目が来ないことを確認。

## 笑顔で喋ると前歯だけ見える問題の修正
- 原因：VRoid の happy（`Fcl_ALL_Joy`）は口の形も含むため、リップシンクの口の形と重なって唇が崩れ、中央の前歯だけが覗いていた。
- 対応：モデル読み込み時に happy を目と眉だけ（`Fcl_EYE_Joy` と `Fcl_BRW_Joy`）の表情に差し替え、口はリップシンクに任せる。`src/` と `app/` の両方に入れた。
- 確認：ミュートしたブラウザで、笑顔と aa/ih/ee を重ねても口が自然に開き、前歯だけが見える状態にならないことを確認。
