# 作業ログ: 2026-09-19

## 作業概要
- BGM再生をハードコードURLからBGM ID指定体系へのリファクタリング
- メインテーマ曲、メインBGM、夜の自室BGM（音量縮小）のプリセット定義と自動解決機能の実装
- タイトル画面（メインテーマ）、ゲームプレイ中（メインBGM）、夜フェーズ自室（夜の自室BGM）の自動切り替えフロー構築
- Vitestによる単体テスト拡充とビルド検証

## 決定・実施事項
1. **BGMプリセットおよびID体系の整備 (`app/src/data/bgmPresets.ts`)**:
   - `BgmId` 型（`'main_theme' | 'main_bgm' | 'night_room' | 'bad_ending'`）を定義。
   - 各曲の設定を `BGM_PRESETS` として一元管理：
     - `main_theme`: `/bgm/thema_music.mp3`（音量スケール 1.0、タイトル画面等用）
     - `main_bgm`: `/bgm/main_bgm.mp3`（音量スケール 1.0、ゲームプレイ中標準用）
     - `night_room`: `/bgm/night_music.mp3`（音量スケール 0.45、夜の自室用として音量を下げて再生）
     - `bad_ending`: `/bgm/bad_music.mp3`（音量スケール 0.8、バッドエンド用）
   - BGM IDまたは直接URLから情報（URL・音量スケール）を解決する `resolveBgmInfo` ヘルパー関数を実装。

2. **オーディオサービス（`SoundManager.ts`）のID指定対応**:
   - `playBgm(target: BgmId | string, volumeScale?: number)` に改修。
   - `BGM_PRESETS` に登録されたIDを渡すと、プリセットURLとデフォルト音量スケール（夜自室の音量縮小等）が自動適用されるように強化。
   - `currentBgmTarget` と `currentBgmUrl` を追跡し、同一BGMが連続再生要求された場合は曲頭に戻さずシームレスに継続再生（ボリュームのみ更新）する設計を維持。
   - 現在のBGM再生情報を取得する `getCurrentBgm()`, `getBgmAudio()` メソッドを追加。

3. **シナリオ型定義およびエンジンの拡張 (`scenario.ts`, `ScenarioEngine.ts`)**:
   - `ScenarioScene` に `bgm?: BgmId | string;` フィールドを追加。従来の `bgmUrl?: string;` は後方互換性のため維持。
   - `ScenarioEngine` の `getCurrentScene()` で `bgm` / `bgmUrl` を正規化して解決。
   - `morningScenarios.ts` のハードコードURL（`/bgm/thema_music.mp3`）を `bgm: 'main_bgm'` へ更新。

4. **画面オーディオ連動ロジックの改善 (`App.tsx`)**:
   - **タイトル画面**: `soundManager.playBgm('main_theme')` を再生。
   - **夜フェーズ（自室）**: `soundManager.playBgm('night_room')` を再生（音量スケール0.45で静かに再生）。
   - **ゲームプレイ中（朝・午前・昼・放課後・場所選択・行動ターン・エンディング）**:
     - シーンに個別指定（`currentScene.bgm || currentScene.bgmUrl`）がある場合はそれを再生。
     - 個別指定がない場合は基本BGMとして `main_bgm` を再生。
   - 依存配列に `gameState.phase` を追加し、昼から夜への移行時や翌朝起床時にも自動で適切なBGMに切り替わるように設定。

5. **テスト・検証**:
   - `AudioServices.test.ts` に BGM ID 指定、URL解決、シームレス継続、夜の自室における音量縮小（0.4未満への減衰）を検証するテストケースを追加。
   - `npm run test -- --run`（全26テストパス、0.27秒）
   - `npm run build`（TypeScriptチェックおよびViteビルドエラーゼロ）

## 第3セッション: タイトル前事前ローディング画面 & 幕間オンデマンドローディング実装

### 作業概要
- タイトル画面前のコアアセット一括事前ロード画面の実装（ヒロイン3人の制服・私服VRM計6体、主要BGM2曲、リップシンクWASMモジュール：計約105MB）
- 白基調（ライトテーマ）による案内文表示と「START（読み込みを開始する）」ボタンによるWeb Audio API（AudioContext）の安全なアンロック
- リアルタイムプログレスバー・バイト数表示・ロード中アセット名表示（スキュー＆ソリッドシャドウ・Kiwi Maruタイポグラフィ）
- 幕間トランジション（`InterludeOverlay`）中の待機によるオンデマンドローディング（待機モーション `Standing Idle.fbx`、移動先背景テクスチャ、シナリオ音声）

### 決定・実施事項
1. **アセットプリローダーサービス (`AssetPreloader.ts`)**:
   - `THREE.Cache.enabled = true` を有効化し、Three.js レベルでのキャッシュ活用基盤を整備。
   - `INITIAL_PRELOAD_ITEMS` に葵・エミリ・紫苑の各制服・私服モデル計6体、`thema_music.mp3`、`main_bgm.mp3`、`lipsync.wasm`、`lipsync-processor.js` を登録（合計約105MB）。
   - ストリーミングダウンロード監視により、バイト単位での正確な進捗率（`0〜100%`）と現在ロード中アセット名をコールバック通知。
   - 幕間待機用の `preloadInterludeAssets` ヘルパーを整備。

2. **白基調ローディング画面コンポーネント (`LoadingScreen.tsx`, `LoadingScreen.css`)**:
   - 白基調（`#ffffff`）、濃紺ボーダー（`#0f172a`）、立体ソリッドシャドウ（`#0b1d47`）、アクセントブルー（`#0284c7`）。
   - 絵文字を一切使用せず、SVGアイコンおよびKiwi Maruタイポグラフィで構成。
   - 案内画面: 余計な内訳詳細文言を排除し、指定通り「本作品をプレイするには、約 105 MB 程度の読み込みが必要です。」と「START →」ボタンに簡略化。
   - ロード中画面: 内部アセット名詳細を非表示にし、シンプルな「データを読み込み中...」ラベル、%表示、進行バー（光沢アニメーション付き）、`X.X MB / 105 MB` 表示。

3. **タイトル画面BGM不鳴動バグの調査・特定および改修 (`App.tsx`, `SoundManager.ts`)**:
   - **原因特定**: `App.tsx` のオーディオ連動 `useEffect` の依存配列に `isInitialLoading` が欠落していた。初期マウント時（`isInitialLoading = true`）にガードされ、ロード完了で `isInitialLoading` が `false` に更新されても再実行されず、`soundManager.playBgm('main_theme')` が一切呼ばれていなかった。
   - **対応**: 
     - `useEffect` の依存配列に `isInitialLoading` を追加。
     - STARTボタン押下時（ユーザー操作コンテキスト内）に `soundManager.unlockAudio()` でメインテーマ用オーディオ要素を事前作成・アンロックし、タイトル画面表示時に確実に再生が開始されるよう強化。
   - 場所移動時、就寝時、やり直し時、ゲーム開始・再開時の幕間演出（`onCovered`）において、次のシーンに必要なアセット（背景・ボイス・モーション）を非同期ロード完了させてからスライスを開くパイプラインを確立。

4. **検証結果**:
   - Playwright による実機ブラウザ自動検証で以下を確認:
     - `loading_prompt.png`: 指示通りの簡潔な文言と「START」ボタン
     - `loading_progress.png`: 「データを読み込み中...」と進捗バー表示
     - `title_screen_loaded.png`: タイトル画面遷移
     - **実機BGM再生状態**: `currentBgm: main_theme`, `hasAudio: true`, `paused: false`, `currentTime: 0.81s`, `volume: 0.4` で正常再生を実測確認
   - `npm run build`（TypeScriptチェック・Viteバンドル成功）
   - `npx vitest run`（全26テストパス）

5. **移動場所選択画面の背景模様をロード画面のデザインへ統一 & 時間帯別カラー連動 (`ActionSelectModal.tsx`, `ActionSelectModal.css`)**:
