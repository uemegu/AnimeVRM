# ギャルゲーアプリ 機能一覧

## 基本ゲーム進行（ゲームサイクル・スケジュール）

- **全体の期間**: 28日間（月曜始まりで4週間 / 7日 × 4週）
- **最終日**: 28日目にエンディングを迎える
- **1日の進行フロー（タイムライン）**:
  1. **朝（登校時）**:
     - 毎朝、朝イベントが1件発生（登校中の会話や登校時ハプニングなど）
  2. **午前（行動ターン1）**:
     - 移動先を選択して行動
  3. **昼（行動ターン2）**:
     - 移動先を選択して行動
  4. **放課後（行動ターン3）**:
     - 移動先を選択して行動
  5. **夜（自室）**:
     - 自室での選択肢:
       - **セーブ**: 進行状況の保存
       - **ロード**: 保存データの読み込み
       - **1日をやり直す**: 当日の朝（または自室開始時）の状態からやり直す
       - **就寝**: 翌日の朝へ進む
- **行動ターンの仕様（午前 / 昼 / 放課後）**:
  - **場所の選択**: 固定の選択肢から選ぶ（例: 運動場、教室、屋上、購買、図書室など）
  - **事前情報**: 誰がいそうか（滞在キャラクターの気配や目撃情報など）が事前にわかることがある
  - **場所ごとの会話・イベント**: 選択した場所に応じた会話やイベントが発生
- **休日（土日）**:
  - 学校が休みのため朝イベントはなく、昼に1回だけ行き先を選ぶ（選択後は夜の自室へ）
  - 行き先は街マップから選ぶ。初期は公園・商店街・映画館・自宅
  - 遊園地・水族館は条件付きで追加される（`unlock_amusement_park` / `unlock_aquarium` フラグ。定義は `data/locations.ts`）
  - ヒロインは私服モデルで登場する
- **日中の強制イベント（割り込み演出）**:
  - 稀に日中も行動選択を挟まずに強制イベントが発生する
  - 例: 未遭遇の重要キャラクターの出会いイベントを自発的に起こさなかった場合に、シナリオ進行上強制的に出会わせるイベントなど

## シナリオの発生条件

`ScenarioPackage` の `availability` で発生条件を指定できます。項目を省略するとその項目では制限されません。`availability` と `actionHints` を省略したシナリオは、すべての行動場所・時間帯で候補になります。既存の `actionHints` は引き続き場所・フェーズの発生範囲とヒント表示に使われます。

```ts
{
  id: 'aoi_followup',
  title: 'アオイとの続きのイベント',
  availability: {
    after: {
      all: [{ scenarioId: 'morning_day_1' }],
      any: [
        { scenarioId: 'action_classroom_aoi', choiceId: 's_accept' },
        { scenarioId: 'action_library_shion', choiceId: 's_recommend' },
      ],
    },
    timeSlots: ['afternoon', 'afterschool'],
    dayRange: { from: 3, to: 10 },
    locations: ['library', 'rooftop'],
  },
  priority: 10,
  scenes: [],
}
```

- `after.all` はすべての条件が必要、`after.any` はどれか1つが必要です。両方指定した場合は、両グループを満たします。
- `choiceId` を省いた条件は指定シナリオの完了を待ちます。指定した場合はその選択肢を選んだ時点で条件を満たします。選択肢の `id` を使い、未指定の場合は `goto` のシーンIDが履歴IDになります。
- `timeSlots` と `locations` はそれぞれ複数指定を OR として扱います。時間帯は `morning`（朝・午前）、`afternoon`（昼）、`afterschool`（放課後）、`holiday`（土日）です。
- `availability.locations` を指定すると発生場所はそちらで判定します。未指定時は `actionHints` の場所が適用されます。同様に、`timeSlots` 未指定時は該当する `actionHints.phases` が適用されます。
- `dayRange.from` / `to` は両端を含みます。時間帯・日付・場所・先行条件は互いに AND で評価します。
- 条件を満たすシナリオが複数ある場合は `priority` の大きいものを選び、同じ値なら定義順を使います。

## 必須（個人開発のブラウザゲームとしての最小構成）

### ゲーム開始・終了

- はじめからプレイ
- 保存した続きからプレイ
- シナリオ終了の表示・最初に戻る
- 基本操作の案内

### シナリオ・会話

- 台詞・地の文・話者名の表示
- クリック・タップによるテキスト送り
- 選択肢の表示・選択
- 選択結果に応じたシナリオ分岐
- 分岐に必要な選択結果・フラグの保持
- **多言語テキストの単一インスタンス管理**:
  - 言語ごとにシナリオ全体を複製せず、1つのシナリオ定義内で各言語テキスト（`text_ja` / `text_en`、またはi18n辞書参照）を保持
- **画面非依存（Headless）の進行・フラグ検証**:
  - 画面（React/Three.js）から独立してシナリオ進行とフラグ制御を単体テスト可能

### キャラクター・背景

- キャラクターの表示・非表示・切り替え
- 背景の表示・切り替え
- シナリオ進行に合わせたキャラクター・背景の更新

### 保存・再開

- ブラウザ内への進行保存（1件）
- ページを閉じた後・再読み込み後の進行再開
- 会話位置・分岐状態・キャラクター・背景の復元
- 保存・読み込みに失敗した場合の案内

### ブラウザでの基本動作

- マウス・タッチによる基本操作
- 対象画面サイズでのテキスト・選択肢の表示調整
- 素材の読み込み中表示
- 素材の読み込み失敗時の案内・再読み込み
